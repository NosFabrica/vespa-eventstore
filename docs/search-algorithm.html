NIP-50 search — how matching and ranking actually work

The full pipeline from a search term to a ranked page, what each knob weighs, and — the honest part — which match paths were silently inert before this branch. Root cause from Brainstorm's 2026-07-30 fix (NosFabrica/brainstorm-k8s#3 + brainstorm_server#64), whose schema and query builder this library's profile group is a port of. The fix is now ported here: the *_parts/*_tokens attribute fields, direct prefix/fuzzy terms, the near tier in every profile, and the re-derived weights all land in this branch — "today"/"before" below describes the pre-branch (and currently deployed) behavior, "after" is what this branch does once a deploy + reindex lands.

1 · The pipeline

tokenizesearch term → whitespace words, every word kept (EventYql); ≥2 words adds a joined variant, ≥3 adds adjacent pairs
→
recallone OR-group per word across all 10 search fields + trigram nets (FuzzyWordGroup) — a word matching any clause recalls the doc
→
ranka rank profile scores every recalled doc: text tiers, then trust (event.sd)
→
cuttext_score_cutoff / min_rank / rank-score-drop-limit discard weak hits before the page is built

Recall is deliberately loose — ranking is supposed to sort the noise out. That division of labor is why a broken matcher hides for months: nothing errors, the doc just arrives through a noisier path and ranks accordingly.

2 · What one query word emits — and what actually runs

For each word, FuzzyWordGroup emits up to four clause shapes per field, plus trigram nets. Two of the four shapes do nothing, verified by Brainstorm against a real Vespa:

clause (as emitted)intentstatuswhy
({defaultIndex:"name"}userInput(@w)) exact whole-token match✓ works feeds matchCount(name) → the token-match tiers
({defaultIndex:"name",prefix:true}userInput(@w)) prefix match ("Ode" → ODELL)✗ silent no-op userInput() does not propagate prefix/fuzzy annotations — the clause parses, runs, and behaves as a second exact match. No error, ever.
({…,fuzzy:{maxEditDistance:1,prefixLength:2}}userInput(@w)) 1–2 typo match ("Odel" → ODELL)✗ silent no-op same annotation drop — and even a direct fuzzy() term would be rejected: prefix/fuzzy require an attribute field, and name/display_name/search_primary are index fields. Cause 1 masks cause 2, so nothing ever surfaced.
name_gram contains "ode" or … (OR net) recall safety net△ works, unbounded any doc sharing a single trigram matches: "ode" recalls model, code. No edit-distance bound exists on this matcher, so no typo budget can constrain it.
about_gram contains "ode" and … (AND net) discriminative bio recall△ works, degenerates short at 1–2 trigrams (words of 3–4 chars) the AND collapses into a bare substring test — "Ode" reaches a bio reading "hosted by ODELL".
label:"mtch_prefix" → match_quality() exact>prefix>typo rank ladder✗ inert itemRawScore never populates for plain text terms (documented in event.sd as KNOWN-INERT). The ladder reads 0 for everything.

Net effect: matching is exact-whole-token OR trigram-noise, nothing in between. Every "fractional" hit — prefix, typo, part-of-a-compound — arrives through the trigram net, scores in the gram band (≤ gram_cap = 80), and is ranked as noise.

Our in-memory reference (SearchFields.matches) is a case-insensitive substring test — strictly looser than any of the above. Tests that assert recall-equivalence against it pass while the real engine misses prefix/typo/compound shapes: the reference promises recall the engine does not deliver. Any port must reconcile this contract (see §6).

Why 2000 is not enough — the trust multiply breaks the ladder

wot_mult() spans 1.0 → ~5.6 (at min_rank=2, log-concave). Tiers only stay ordered if each band's floor × 1.0 clears the band below's ceiling × 5.6. Measured upstream at w_name_tier=2000: a max-trust bio mention ((550+130)×5.6 ≈ 3800) beat a floor-trust exact name match (~2100) — searching "coffee" put 126 bio-only accounts above the account literally named "coffee". Their re-derivation:

bio ceiling   (550 + 130) × 5.6  ≈   3 808
weak floor    w_weak_tier        =   4 000   >   3 808 ✓   (infix + hashtag prefix)
weak ceiling  (4000 + 80) × 5.6  =  22 848
near floor    w_near_tier        =  23 000   >  22 848 ✓
near ceiling  (23000 + 80) × 5.6 = 129 248
exact floor   w_name_tier + 100  = 130 100   > 129 248 ✓   → w_name_tier = 130 000

The invariant to re-derive on any weight change: w_name_tier + 100 > (w_near_tier + gram_cap) × max(wot_mult) and w_near_tier > (w_affil_tier_text + ~130) × max(wot_mult) — and one more rung down for w_weak_tier. This branch ships the four-rung values above; the deployed pre-branch schema still has 2000, where the "coffee" inversion is live.

6 · The upstream fix, and what our port must adapt

Brainstorm's two-PR fix (schema: brainstorm-k8s#3 · query: brainstorm_server#64):

  • Two attribute fields derived from name + display_name, both load-bearing: name_parts (split at every word start — camelCase + non-alphanumeric runs, Unicode-aware so Cyrillic/CJK/accents survive) and name_tokens (whole lowercased tokens — without it "vitorp" → "VitorPamplona" regresses, since parts splits it into [vitor, pamplona]).
  • Direct terms — name_parts contains ({prefix:true}@w) / ({maxEditDistance:N,prefixLength:2}fuzzy(@w)) — never via userInput(); only the top edit distance emitted (it subsumes the smaller ones).
  • Bounded matchers replace unbounded recall: length-gated typo budget capped at 3 (≈22–25% of the word, Meilisearch's ratio); name-side trigram OR off; about_gram gated to ≥3 trigrams; prefix floor 3 Latin / 2 non-ASCII; synthetic joined/pair variants get prefix but no fuzzy (a 22-char concatenation drew the top typo budget — the most expensive matcher — for a token nobody typed).
  • A real near tier in every profile, gated so exact ≻ near ≻ identity ≻ affiliation ≻ gram never stack or invert; weights re-derived to survive the ×5.6 trust multiply (§4).
  • Gate consistency: affiliation_match_text/secondary_active_text key on name_match() so a common-domain nip05 hit no longer zeroes genuine bio credit.
  • Tooling: rank_ab.py + 33 regression cases (query → expected pubkey), and 19 YQL-shape unit tests that provably fail against the pre-fix builder.

Round 2 — beyond the upstream port

A second pass took the algorithm past what Brainstorm shipped:

  • Feed-side derivation (NearText) replaces the schema-side split: doc and query now share one normalization (NFKD diacritic fold + lowercase), so "jose" reaches "José" — string attributes match raw bytes and Vespa's linguistics never applied to them. Tokens also index alnum-stripped and whole-name-joined variants ("vitorp" → "Vitor Pamplona"), and CJK runs index their suffixes ("太郎" → "中村太郎"). Deploy consequence: populating these needs a RE-FEED, not a reindex — feed-computed fields can't be rebuilt from Vespa's document store.
  • The weak tier restores bounded infix ("dell" → ODELL via an AND of every query trigram — the regression the upstream port accepted) and adds hashtag/summary prefix reach (search_secondary_tokens, prefix-only). The ladder re-derives to 130000 / 23000 / 4000 / 550 so all four rungs survive the ×5.6 trust multiply.
  • Second-phase precision on search/text2: the words rule (query coverage) and exactness (whole-field match), computed over the top 1000 hits only and bounded to reorder within a band. A within-near ordering by character coverage ("Ode"→"Ode" above "Ode"→"Odessa") is deliberately absent — fieldMatch/elementCompleteness are token-granular, so that signal needs a custom searcher, not a rank expression.
  • Measurement: searchScored labels every hit with its tier; RankRegressionIT asserts the whole canonical corpus (positions + tiers) against a real Docker Vespa — including that the second-phase fieldMatch features deploy — and :benchmark:rankAb A/Bs any knob against rank_cases.json live, with no deploy/reindex/re-feed. Add a case every time someone reports a bad search.

Not yet verified here (no Docker in this environment): run ./gradlew :benchmark:test -Pintegration where Docker is available before deploying — it is both the ranking regression gate and the schema deploy check.
